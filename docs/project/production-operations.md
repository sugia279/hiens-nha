## Ingress finding and implementation boundary

The current database intentionally grants public SELECT on comments/entities to anon/authenticated and own-profile/history/audit reads to authenticated, protected by RLS. Eight SELECT grant rows match the foundation migration. Read RPC EXECUTE grants also exist. This is not a new permission leak, but callers can bypass the Edge worker's connection guard. Mutation authority/quotas do not bound public-read request volume. Catalog checks found no applicable role/database `pgrst.db_pre_request` setting; they do not inspect provider gateway/WAF settings.

The official [Data API security guide](https://supabase.com/docs/guides/api/securing-your-api#pre-request-checks) documents pre-request checks, but its counter-writing rate-limit example excludes GET/HEAD because they run read-only. Adding that example alone cannot establish global read limiting. Do not trust arbitrary forwarded headers, disable RLS, replace caller JWTs with service-role CRUD, or treat CORS/timeouts as request admission.

PR35 now implements the application-layer scope in [ADR0009](../decisions/0009-shared-read-admission.md) and migration `20261116115121_shared_read_admission.sql`: metered volatile POST RPCs, no direct table SELECT grants for browser roles, fixed global/class counters, and the matching caller-JWT Edge adapter. Existing mutation RPC wrappers also charge admission so idempotent replay cannot become an unmetered read path. Mutation authority,30/member and120/owner per-minute quotas remain unchanged. Existing private publication/request checks are reused; the comment projection explicitly enforces existing entity/author/owner/root visibility. Four fixed rows bound counter retention; there are no IP or user identity counters. Global/anonymous/member/owner initial RPC-call caps are300/200/240/120 per DB second. These are reviewable settings, not measured capacity or per-client fairness.

The migration and Edge changes are **source only, not deployed**. New Edge expects the RPC migration; old Edge table reads fail after the revoke, so review/deploy the pair in the frozen-writer maintenance window before any source-marker change. CI adds a disposable native PostgreSQL12-call concurrency/cap/reset test and real-JWT direct-table/POST projection denials. Hosted performance and anonymous/member/owner runtime evidence for this new version remain required; no hosted test rerun or synthetic production data is authorized here.

Successful RPC transactions share budgets across workers/direct POST calls; GET/HEAD RPC is rejected. Failed transactions roll back admission counters, and one-second fixed windows permit boundary bursts. Global/class row locks can add contention. The private stable projection is operator-only and keeps the read-only exported snapshot recovery compatible; browser roles cannot call it. The existing pre-migration recovery path is retained for production's currently deployed schema. Source backup reads remain read-only; only isolated restore verification uses writable transactions.

This is an application/DB admission layer, **not a global gateway/WAF**. Edge/Auth/Data API gateways still receive traffic, including rejected, invalid-token and failed calls; invocation/egress exhaustion and direct-origin volumetric traffic are not bounded by this migration. A trusted ingress/proxy that prevents origin bypass remains a separate hosting/account/cost and residual-risk decision. No Redis/proxy/WAF/paid service is created. The complete ingress gate stays open pending hosted rollout evidence and that scope decision; the accepted staging performance exception does not waive it.
