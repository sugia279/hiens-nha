# Guest social API — ADR0019

Supabase Anonymous Auth issues a caller JWT before the first public comment/reaction. This is an authenticated SQL actor, not the unauthenticated `anon` role. Actor identity comes exclusively from `auth.uid()`; anonymous status comes from `auth.users.is_anonymous`, not submitted metadata. `/me` adds `guest:true` only for guests and retains the existing member/owner response for verified accounts.

Existing comment routes and `post_reaction_set` retain their signatures, receipts, validation, CAS, owner moderation, quotas and source/epoch/writer checks. Guests can use existing comment surfaces only for public entities, and post reactions only for published, undeleted posts. Guests cannot publish content, upload, create categories, mutate Requests, moderate or acquire owner authority. Private implementation functions renamed `_pre_guest` are explicitly inaccessible to browser roles. Anonymous JWTs share the **anon** read admission bucket and existing 30/minute actor mutation limits.

All additional RPCs use POST, the existing publishable key and optional verified caller JWT. No service-role client. Private RLS tables have no browser grants; wrappers remain invoker functions with empty search paths and scoped private definer implementations.

| RPC | Input | Output / authorization |
| --- | --- | --- |
| `guest_identity` | `p_name:text=null`, `p_choose:boolean=false`, `p_proof:uuid=null` | Guest JWT required. Returns `{display_name,chosen}`. Read creates an empty caller-owned profile if needed. `p_choose=true` stores a trimmed 1–60 character name, or `Người Lạ` for null; control characters rejected. Cancellation records `chosen=true`. |
| `guest_identity` (OAuth preparation) | Fresh unpredictable `p_proof`, no actor ID | Stores only SHA-256 of the proof, with a five-minute expiry. Rotates the caller's previous proof. Name/proof mutations share actor quota. Proof stays in browser memory, never browser storage. |
| `guest_claim` | `p_proof:uuid` | Verified account JWT required. Derives source from the proof and destination from `auth.uid()`. Transfers current guest comment ownership and reactions only. Existing destination reactions win conflicts; one row/account/post remains. Preserves historical receipts/revisions/audits. Gates apply for affected features. Successful replay is idempotent only for that same destination within expiry; guessed, expired, guest-caller or other-account redemption is 403. Transferred guest JWTs cannot keep writing. Returns `true`. |
| `post_reaction_details` | `p_id:uuid`, `p_after:uuid=null`, `p_limit:int=25` (1–50) | Public read; only undeleted published posts, otherwise 404 even for owner. Returns `{items:[{display_name,avatar_url,reaction}],nextCursor}`. Cursor is a dedicated random reaction-row cursor, never an actor/auth ID. Keyset pages may reflect concurrent additions/removals; no snapshot/realtime promise. |

Every RPC consumes shared admission once. Guest profile choice/proof writes are bounded by the existing guest actor mutation window. Unknown kinds, invalid names/bounds are 422; admission/quota is 429; maintenance is 503. No direct public actor enumeration RPC is added. Details never contain email, Auth UUID, provider credentials or tokens. Avatar URLs are HTTPS on supported provider avatar hosts; default guest avatar otherwise. User-entered names render through textContent and never convey role.

Comment list/feed/reply DTOs add optional `display_name` and `avatar_url` without removing existing fields. Author edits/moderation/create responses retain the existing row shape; refresh uses the display projection. Imported authors remain unclaimed. Heart/Laugh/Wow storage stays unchanged; Laugh renders as Smile 😊. Summary reads still return only counts and caller selection.

Guest credentials use scoped sessionStorage for same-tab navigation/reload. Verified sessions retain scoped localStorage until logout/removal/revocation. Both strip provider tokens; PKCE and handoff proof stay in memory. Failed/refused OAuth restores the guest session. Successful OAuth never resubmits the original interaction. Reload during an unfinished OAuth flow abandons its in-memory proof while preserving saved guest records; the still-persisted guest session can start another attempt before exchange. Reopening a closed tab is subject to browser session restoration behavior; storage unavailable falls back to memory.
