# ADR 0003 — Phase 3 publications and Phase 4 requests, local/CI

Accepted continuation on 2026-11-15. Start from `91e3d6a`; main `f3efbf3`; PR #21 remains draft. No production merge/cutover, cloud account or billing choice.

## Decisions

- Posts and media share revision lifecycle/storage but retain separate validators and endpoints. Typed `private.publications` + `publication_revisions` keep author, feature, working/published pointers, title/body/type/category/URL/provider, tags and series FK fields. JSON is only RPC transport/DTO, not a replacement for lifecycle/FKs. Immutable content revisions, append-only audit, exact-revision moderation and optimistic aggregate version checks. Rejected drafts never replace a published revision. Owner can unpublish; author alone edits/deletes their text.
- Series are namespaced by verified author UUID; order slots reserve active working/published positions and prevent two publications occupying one position. Tags/categories have relational registries. New editors provide safe Markdown subset preview (DOM construction, no executable HTML/MDX), preserved poem lines, serial server autosave after valid input, revision history, and safe canonical provider preview for media. Existing MDX/chapters stay static.
- Requests retain the existing status graph, same-status progress updates, owner-only transitions, completion result and scope-reset business. Publication approval is separate from acceptance. As in the legacy contract, editing an approved request keeps its public approval but resets operational state to new, accepted scope and current result; the new scope must be accepted again. Scope/transition races lock the same row and compare both version and scope revision. History is append-only; correction is a new event rather than editing old events.
- All new tables live in a non-exposed private schema, have RLS enabled and no client table grants. Narrow public invoker RPC wrappers call pinned-search-path private functions which enforce caller, owner, visibility, quota, source/write switch, idempotency and CAS. Safe DTO projection selects published revisions for visitors and working revisions only for author/owner. Direct RPC bypass is tested.
- New entities use stable UUIDs independently of language, including query-based static shells `/community/post/?id=...`, `/community/media/?id=...`, `/requests/detail/?id=...`. Entity/comment visibility follows the linked publication/request. Old routes remain generated; old archives are never rewritten by these APIs.
- Separate repository/DB source controls for posts/media/requests remain Git/epoch 0 and disabled. Loopback-only API overrides enable local rehearsal. Archivers skip only their own migrated feature. Import/cutover of existing posts/media/requests is a separate staged operation: inventory/dry-run and preservation contracts before final delta; never flip back to stale JSON after DB writes.

## Gates

Fresh migrations; visitor/A/B/owner negative tests; public old revision survives unapproved edit; direct RPC cannot self-approve or change authors; series collisions scoped by owner; safe URL/Markdown fixtures; request acceptance vs approval, completed/result, scope reset, stale versions and edit-vs-complete race; browser save/submit/approve/read/edit workflows; VI/EN shells and existing static gates; real local Supabase in CI. Real provider OAuth/staging/production/load/backup gates remain separate.
