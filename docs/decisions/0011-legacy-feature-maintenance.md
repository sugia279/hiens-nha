# ADR 0011: Independent maintenance for remaining legacy features

Status: prepared, 2026-11-17. All three flags in `config/legacy-features.json` default to false. This preparation does not freeze production or change source/epoch/API writers. Comments keep their separate ADR0010 marker and existing API authority.

Posts, media and requests need a publication boundary before final reconciliation, while their source still reads Git and their API writer is off. Their current source-only archive skip happens too late to establish that boundary. Add independent version1 boolean flags, shared by each feature's archive CLI and legacy VI/EN submission surfaces. Invalid, missing, mistyped, unknown or unsupported maintenance settings fail closed; the archiver checks before event parsing, GitHub calls, label creation or archive writes. Existing parsing/provenance and approval/acceptance/owner-update rules remain unchanged. The `Archive guestbook` workflow and Pages coupling are preserved; do not cancel or disable the shared workflow.

When a separately reviewed commit activates one flag, its Git forms become a localized maintenance notice. Approved content and routes remain. Requests also remove the board submission invitation and detail-page invitation to add GitHub updates; current scope/status/timeline/result stay visible. Other feature forms/writers remain independent. These Git-only notices cannot enable an API writer and do not replace DB CAS/epoch/authority. API panels continue to use their existing source/epoch/writer gates.

This is an application publication boundary, not a GitHub edit lock. Older admitted checkouts, already open pages and direct GitHub edits can still exist. At activation record exact merge/deployment boundary, inspect and normally drain every previously admitted archive run, capture stable main and complete paginated raw live issues/comments, and explicitly reconcile late changes. Never archive/import blindly or replace original receipts to match normalized parser output, especially media Issue17. No fresh hosted load or synthetic production content is authorized by this preparation.

Comments currently use API1 with its writer enabled. Legitimate real-content submission/private-pending/public-approval verification remains open. Prepare these remaining controls now; do not infer that comments validation or the remaining cutovers are complete. Activate and cut over each feature separately only when its required gates and the preceding comments validation are satisfied. Use audited expected-state source/writer transitions and matching frontend deployment. After API writes, stale Git rollback remains prohibited: freeze the API writer, retain a fresh encrypted recovery point and reconcile the private delta first.

Verification covers independent maintenance combinations, fail-closed markers and actual no-event/no-token CLI early exits. Build smoke reads the exact versioned flags and requires either the original Git forms, a notice without Git continuation/update invitations, or the API panel at its reviewed epoch. Isolated open and individually frozen builds preserve all routes/approved content; temporary build flags are restored before publication. These offline checks do not prove hosted drain, OAuth, actual writes, performance or recovery.
