# ADR 0010: Freeze legacy comments separately from API cutover

Current status — 2026-11-17: legacy comments were frozen by PR38/a582078 and remain frozen. PR39/a718753 deployed the matching commentsAPI1 frontend; a second audited CAS now enables only its API writer. Original default-false/prepared descriptions below are historical. Other feature writers remain independentlyGit0/off; no GitHub edit immutability is claimed. See [actual execution](../project/comments-cutover-2026-11-17.md) and [numeric writer evidence](../project/backend-comments-writer-2026-11-17.json).

Status: prepared, 2026-11-16. Default `config/legacy-comments.json` is version1/frozen=false. This preparation does not freeze production, switch a content source or enable a DB writer.

The existing archive source guard stops Git publication only after the API source marker changes. Final reconciliation needs an earlier boundary while the website still reads its Git snapshot and the API writer remains disabled. Add an independent, versioned boolean maintenance marker shared by the guestbook archiver and both VI/EN submission surfaces. Invalid/missing markers fail the archive/build rather than reopening writes. The archiver checks the marker before event parsing, GitHub calls or file writes. Other feature archive adapters keep their current behavior and the workflow name/deployment coupling is unchanged.

When a reviewed commit activates the marker, the deployed Git guestbook/page comments keep approved messages but replace submission controls with a maintenance notice and remove reply invitations. API comments do not consult this Git-only marker; their own source/epoch/DB authority remain mandatory. Disabling maintenance alone cannot enable API writes.

This freezes this application's legacy publication and new-page submission paths. It cannot prevent edits through GitHub, submissions from an already open old page, other collaborators or jobs that checked out an older commit. Do not call those inputs immutable. Record the merge/deployment boundary; drain every previously admitted archive run; fetch stable main, all matching live issues and paginated comments; retain late arrivals/deltas for explicit reconciliation. Recheck before enabling an API writer. Do not disable the entire archive workflow, cancel jobs, silently drop submissions or alter unrelated feature writers. Only then align DB/frontend source and epoch through the existing audited expected-state model.

Before an API write, the same reviewed flag may reopen Git publication after checking late-input reconciliation and matching sources. After an API write, keep Git publication frozen and use the existing freeze/recovery/delta procedure; never restore an old Git snapshot as the active source.

Verification: regression tests cover independent source/freeze combinations and invalid markers; build smoke checks use the explicit marker and require either the existing Git form, a maintenance notice without Git submit/reply controls, or the API panel with the reviewed epoch. Build both open/frozen Git configurations before activation, preserving routes and approved content. A local no-credential frozen archiver invocation must exit before reading any event. Native authority/load/browser evidence stays separate and is never inferred from this marker.
