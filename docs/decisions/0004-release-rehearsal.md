# ADR 0004 — Phase 5 release rehearsal, local first

2026-11-15, continuing from `98360ac`, branch `feat/backend-foundation`, PR #21 draft. Production remains Git/Issues/Pages; no cloud resources, billing or cutover.

- Rehearse all four submission imports in the disposable local stack. Retain raw versioned evidence, null legacy ownership, approval/tombstones, canonical source URLs and shared legacy series in an explicit namespace. Do not invent authors or timestamps for hand-authored records; record a fixed snapshot timestamp in the import plan. New authored series remain scoped by verified UUID. Import deltas require review and cannot overwrite API history.
- Write gates lock the relevant settings row in SHARE mode for the transaction; maintenance takes its update lock and waits for admitted writes. Operator tooling uses expected state/epoch, records source changes privately, and refuses a Git rollback after any API writes. After writes, rollback means read-only + private backup/delta reconciliation, never a stale JSON flag flip.
- Backups for rehearsal include application schemas and local Auth schema, use native PostgreSQL custom dumps, checksum/count reconciliation and restore into a uniquely named temporary DB in the same disposable cluster. Restore verifies grants/RLS/caller behavior and remains read-only. This proves local logical recovery, not hosted provider configuration, offsite encryption/retention or Storage-byte recovery. Storage is currently disabled.
- Keep durable mutation quotas in DB. Bound Edge connection bursts per worker without trusting client-forwarded IP headers. That bound is not a global distributed IP limiter: hosted ingress/abuse controls remain a staging gate. Structured logs include request ID, route template, duration, status/code, never tokens, raw URLs, IPs or bodies.
- Add an open-arrival Node harness (no extra cloud service) with separate 10/20/50 RPS phases, public vs authenticated latency, 80/20 read/write workload, fixture identity pool, reconciliation and cleanup. A short CI profile validates the harness; the full profile is required for the specified duration gates. Local CI numbers do not establish Vietnam/staging latency or an SLA.
- Staging/release checklist requires verified owner OAuth app/UUID, project/region/tier/budget, secrets entered outside chat, hosted abuse controls/monitoring/restore/load evidence and explicit feature cutover signoff. No production flip is part of this change.
