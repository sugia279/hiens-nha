# ADR0013 — Seven-day browser sessions and owner status composer

**20 November 2026:** [ADR0016](0016-inline-post-interactions.md) supersedes only the seven-day retention deadline at the user's explicit request. Session scoping, provider-token/PKCE exclusions, server verification and device logout remain. The rest of this ADR records the earlier policy and unchanged composer/Storage design.

Accepted 19 November 2026 at the user's request. This supersedes ADR0007's memory-only session lifetime and the browser-storage prohibition only for this scoped Supabase session. GitHub photo-upload tokens and PKCE verifiers remain memory-only. The stable storage key is scoped to this Supabase project and site base path. A custom SDK storage adapter preserves an absolute seven-day deadline across token refresh, removes GitHub provider tokens, and falls back to memory when browser storage is unavailable. The application re-verifies identity/role using `/me` before enabling private operations. A persisted user object is never authority. Logout clears this device's stored session and propagates through the SDK to other tabs. Seven days is an application retention window, not a new server-enforced Supabase session setting; existing JWT expiry/revocation behavior remains.

Home remains owner-only for posting. A dedicated status modal replaces the inline full account editor, without removing the existing account editor. Avatar/name, manually entered people/place/feeling, text, up to four JPEG/PNG/WebP photos and public/only-me selection are supported in VI/EN. People tags do not resolve accounts or send notifications; locations do not request geolocation. Text remains inert. A short title is generated for existing post routes, while social metadata stays optional on each moderated revision. No source/epoch or role assignments change.

Images are resized/re-encoded to WebP (maximum 1600px/2MB each), stripping camera metadata. A private `post-images` Storage bucket admits new immutable owner-prefixed image paths. Reads use caller-aware authenticated downloads and temporary in-memory blob URLs. Anonymous reads require a reference from the exact published revision of a non-deleted post. Draft-only images remain inaccessible to guests/members. Unreferenced uploads can be cleaned up by the owner; referenced historical files cannot be deleted through the client policy. Database backups include metadata/references, but the existing DB-only recovery does not archive Storage object bytes; object backup remains a separate operational limitation.

Saving only-me leaves a private draft and, when editing a public post, explicitly unpublishes it. Publishing uses the existing versioned draft → submit → exact-revision owner approval sequence with idempotency. Editing retains social metadata in the account editor. The feed shows owner posts newest first; only verified owners can additionally see their own drafts and edit them. Guest comments link to the existing per-post discussion.

Deploy additive SQL to staging then production and the updated Edge API before the frontend. Test compatibility, RLS for image bytes, metadata validation, refresh/deadline/logout/cross-tab races, dialog cancellation, hidden/public rendering and uploads in disposable fixtures. Never create hosted test posts. Rollback frontend/Edge together while retaining the optional JSON column, image objects and audit/history; do not drop uploaded assets.
