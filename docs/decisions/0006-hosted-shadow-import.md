# ADR 0006 — Operator-only hosted shadow import

Owner authorized production migration/cutover; hosted project and real owner identity are now verified. Existing network import CLIs deliberately accept loopback only. Keep those guards and add an offline operator packet preparation/rehearsal path; no public import endpoint or client grant.

- Build comment contexts afresh in a temporary ignored directory with backend disabled; require the data, source, migration tooling/schema and build inputs to match the explicit source commit. Reuse the existing comments/publications/requests plans and apply/reconcile models against an empty embedded PostgreSQL rehearsal. Reuse the same migration bootstrap in embedded and disposable native PostgreSQL tests. No Auth users are created by packet preparation.
- Capture only an explicit allowlist of imported content/provenance tables. Never copy Auth, profiles, roles, source controls, quota counters or runtime idempotency receipts. Legacy authors/actors remain null. Authored MDX/assets/photos remain in Git.
- Serialize typed row batches through PostgreSQL `jsonb_populate_recordset`; quote all JSON as escaped literals and choose a dollar delimiter absent from the complete block. User content remains data, including quotes, backslashes and dollar tags.
- The target project ref is explicit metadata matching the reviewed hosted deployment. The operator must pass that same project ref to MCP. The DB packet asserts exact migration versions/schema, RLS, all Git0/disabled controls and the complete initial content footprint, locks controls/import tables and imports atomically. No DELETE, existing-row UPDATE, GRANT or source flip.
- A deterministic transport receipt uses the existing private import_runs ledger. Identical packet/source replay is a no-op only after complete content/provenance equality. Only generated audit IDs/preparation timestamps are excluded from replay equality; legacy business timestamps, bodies, status, revisions, mappings and ownership remain checked. Drift fails; partial failure rolls back the receipt and all rows. New legacy deltas require separate review, never silent overwrite.
- Verify public projections with the existing anon/RLS reconciliation and generated shadow assertions inside the atomic apply; pending/deleted items remain private. Rehearse first apply, replay, drift refusal, disabled controls and unchanged pre-existing owner/profile in local tests, plus a disposable native DB in CI.
- SQL packets contain raw legacy provenance and potentially pending text: mode0600, ignored operator directory, never Git/logs/artifacts. Refuse symlink directories and existing output files; use exclusive creation and clean only the newly created temporary build directory. Persist only hashes/counts and redacted results. Packet preparation has no network apply option.
- Initial shadow import does not freeze the Git writer or complete cutover. Before enabling an API writer: drain/freeze legacy input, review final delta and parity, complete hosted recovery/ingress/load/session gates, then align source/epoch and activate exactly one writer per feature. No hosted p95 or recovery claim follows from this packet.

PostgreSQL [typed JSON record expansion](https://www.postgresql.org/docs/17/functions-json.html) and existing DB constraints remain authoritative. Current project is PostgreSQL17.11; no new schema or permission change is needed for this transport.
