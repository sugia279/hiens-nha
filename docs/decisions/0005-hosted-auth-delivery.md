# ADR 0005 — Hosted Auth delivery before content cutover

Accepted scope: owner authorized main merge and production cutover, then created the GitHub OAuth App and saved its credentials in Supabase on 2026-11-15. This checkpoint enables verified login configuration while content remains Git-backed; it does not complete content cutover.

- Use the existing Supabase project, GitHub provider, exact VI/EN callback URLs and Pages origin. Store only browser-public project/API configuration in Pages inputs. Keep all DB source controls Git/epoch0/writes=false until final import, identity and operational gates pass. No synthetic hosted identities or content, no privilege inferred from profile metadata.
- Auth-enabled builds include the lazy Auth SDK even while content sources remain Git. The measured emitted JS inventory is691,506 bytes across mutually exclusive routes; every route satisfies the existing600,000-byte ceiling. Extend ADR0002's complete per-route static/dynamic dependency measurement to hosted Auth-enabled builds. Retain600,000-byte JS per route and100,000-byte CSS aggregate/per route; report total JS inventory. Keep the old aggregate JS gate for backend-disabled builds.
- Emit a strict `data-backend-enabled` boolean on the built document root. The budget CLI derives policy from this artifact, not from its later shell environment. Missing markers retain the aggregate gate; invalid or inconsistent document markers fail. `--pilot` cannot bypass a disabled artifact's aggregate gate. Missing/untracked/lazy manifest edges remain errors. Tests must prove enabled routes still fail on oversized lazy JS and CSS, and disabled inventory still fails above its original ceiling.
- Preserve265 existing routes/84 chapters, source markers and legacy business. Auth-only delivery keeps the current Git writer until each replacement source is ready. User requested no GitHub continuation button after the later API cutover; API-mode UI already omits it for all roles.
- Sessions remain page-memory PKCE popup sessions. Reload/full navigation requires sign-in again; no tokens/verifiers in browser storage. Real provider consent/callback and verified GitHub provider identity must be observed before owner bootstrap. Enabling a provider alone is not proof of website login, working moderation or safe content cutover.
- Local/CI build budgets are not hosted latency, load capacity, ingress protection or recovery evidence. Hosted10/20/50 RPS text workload and p95<2s remain a measurement gate.
